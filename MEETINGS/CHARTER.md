# MEETINGS — 「最高に面白いゲーム」徹底議論ミーティング規約

開始: 2026-08-03（ユーザー指示）。
目的: **どうしたら最高に面白いゲームに仕上げられるか**を職能横断で徹底議論し、採用可能な形（提案書）に落とすこと。

## 大原則

1. **ミーティングはコードを書かない**。成果物は議事録＋提案書のみ。
2. **計画文書（ROADMAP / SCOPE / DECISIONS / BACKLOG / PARALLEL_SESSIONS）は編集しない**（編集権はSセッション）。採用判断はユーザー → 採用されたものを S が計画へ反映する。
3. **3本柱は不変**: ①1日1回 ②監督主人公 ③漫画風（DECISIONS/VISION）。議論してよいのは「その中でどう面白くするか」。ただし reframer だけは前提そのものへの問いを1つ出してよい（採用ゲートは同じくユーザー）。
4. 事前に必読: `VISION.md` / `SCOPE.md` / `GAME_PLAN.md` / `ROADMAP.md` / `DECISIONS.md` / `BACKLOG.md`（現状把握なしの理想論は却下対象）。

## 参加者とレンズ（サブエージェント）

| 参加者 | レンズ |
|---|---|
| reframer | そもそもこのゲームの「面白さの核」は何か。前提を疑う担当 |
| engine-dev | 試合エンジン起点のドラマ・駆け引き・采配の手応え |
| renderer-dev | 漫画演出・決めゴマ・迫力とテンポ |
| ui-designer | UX・テンポ・1画面1ビート・触って気持ちいいか |
| data-steward | 選手データ・個性・物語素材としてのリアリティ |
| gtm-strategist | 市場視点。競合ヒット作は何が面白いか・刺さる面白さの型 |

## 進行フォーマット（議長=メインセッション）

1. **Round 1 独立提案（並列・ブラインド）** — 各参加者が他者の案を見ずに「このゲームを最高に面白くする打ち手」を提案（各2〜3案。①何が面白くなるか ②具体的な形 ③実現コスト感）。
2. **Round 2 相互批評** — 全案を突き合わせ、批評・補強・合体。reframer が「そもそも」の挑戦を1本入れる。
3. **Round 3 議長統合** — インパクト×実現性でランク付けし、G/D の担当・SCOPE の★等級に紐付けて提案書化。

## 成果物

- 議事録: `MEETINGS/YYYY-MM-DD_NN.md`（全案・批評・結論を記録）
- ユーザー向けサマリー: 採用候補トップ3〜5（各: 何が面白くなるか／形／コスト／担当と入れ先）＋見送り案の理由一行
- 採用判断は**ユーザーのみ**。ミーティングが勝手にスコープを増やさない（凍結ルール準拠）。
