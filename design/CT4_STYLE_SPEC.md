## 1. ★ 情報源の切り分け（ここを間違えると全部ずれる）

動画から取れるものと取れないものを、実測して確定させた。

| 項目 | 動画から取れるか | 根拠 |
|---|---|---|
| 構図・ゾーン比率・選手の画面占有 | **取れる**（読み取り精度） | 幾何は圧縮で壊れない |
| モーションのコマ数・尺・カメラ挙動 | **取れる** | 時間方向の情報は残る |
| ビートの順序と構造 | **取れる** | 同上 |
| **色数・パレット・ブロック幅** | ✕ **取れない** | 下記 |

**✕ の理由（実測）**: 動画のアクション帯を測ると **色数 134,206／1タイル最大64色／ベタ面のラン長中央値 1px／16色超のタイル 61%**。
SFCの上限は 1タイル16色・画面256色なので、この数字は**全部 YouTube 再エンコードのノイズ**である。
256×224 を 1280×720 へ引き伸ばして再圧縮しているため、ベタ面が完全に破壊されている。

→ **色とドットの基準は動画ではなく SFC のハードウェア仕様から決める。**

## 2. 受入基準（機械検査できる形）

★ これが本仕様の最大の価値。今日まで層Cで揉めた「画風が割れているが基準が無い」は、
**目標が数値化されていなかった**ことが原因だった。CT4準拠にすると基準が客観化する。

| # | 基準 | 値 | 検査方法 |
|---|---|---|---|
| A-1 | 論理解像度 | **256×224** | 画布サイズ |
| A-2 | 1タイル(8×8)の色数 | **16以内**（15色＋透明） | 8pxグリッドで走査し最大値 |
| A-3 | 画面全体の色数 | **256以内** | ユニーク色を数える |
| A-4 | 8pxグリッド整合 | スプライト境界が8の倍数 | bbox が8で割り切れる |
| A-5 | ベタ面率 | **不透明画素のうち長さ3px以上の水平同色ラン(tol=16)に属する割合 ≧ 50%** | 画素加重のラン走査 |
| A-6 | アンチエイリアス | **禁止**（中間色を作らない） | 隣接色の階調数で判定 |

**asset-qa をこの6項目のゲートとして書き直す。** 層C素材（`tools/asset_accept_layerc.py`）と同じ形式で機械判定にする。

| M-01 | 走り／ドリブル | ✅ 採取済 | **複数コマのループ・サイクル 0.4〜0.6秒**。0.1秒刻みで全コマ別ポーズ |

**★ M-05で発見した「ボール飛行の専用ビート」（約0.8〜1.6秒）**
ロングパスの滞空中、**カメラがスタンドの引き画に切り替わり、ボールだけが空を横切る**。
選手は誰も映らない＝ボールが唯一の主語。1ショット1主語の徹底例で、
football-sim のロングパス拍1（蹴り出し）と拍2（受け）の**間に挟む中間ビート**としてそのまま使える。
層S（引き画）の第2の使い道（溜めに続き2つめ）。

**追加の観察（同シーケンス内）**
- **ガッツが保持中も減り続ける**: 画面表示で 509→503→500→494→491（約4秒＝毎秒4〜5）
- **試合中に選手のステータスカード**（ドリブル/シュート/パス/ガッツの数値表）が一瞬挟まる
- **プレー中の掛け合いカットイン**: 顔アップ＋集中線のベタ背景。**色が感情/文脈で変わる**（青・赤・緑を確認）

**共通の挙動（M-01で確認）**
- 選手は**画面中央付近に留まり、背景がスクロールする**（カメラ追従）
- **ボールは選手と独立に動く**（足元で小さく弧を描く）
- **行動値の数値が動作中にリアルタイムで減る**（画面上で `386→383`）
- 試合時計もリアルタイムに進む

## 8b. 採取パイプライン（確立済み・ブラウザ不要）

ブラウザ経由の採取は**バックグラウンドタブのデコード停止**で偽の静止フレームを掴む（2026-07-30に実証）。
以後は**ローカルにセグメントを落としてffmpegでコマ分解**する:

```
python3 -m yt_dlp --ffmpeg-location "$(python3 -c 'import imageio_ffmpeg;print(imageio_ffmpeg.get_ffmpeg_exe())')" \
  --extractor-args "youtube:player_client=android" -f "b[height<=720]/b" \
  --download-sections "*<開始秒>-<終了秒>" -o "seg.mp4" "<URL>"
# → fps=1 で全体俯瞰 → 対象窓だけ fps=5 で精査（drawtext でタイムスタンプ焼き込み・tile で1枚に）
```
- 60秒セグメント≈3.7MB・数秒で取得。M-07等の残りはこの手順で埋める。
- 分析用の中間物はスクラッチパッドに置く（リポジトリに入れない）。
